# B9.3 — Làm giàu misconception để feedback chạm tầng cao nhất

> Acceptance criteria, viết trước khi code theo CLAUDE.md §6.

## Bối cảnh

Hai khoá sắp chạy (`thiet-ke-ui-ux`, `tieng-trung-co-so-3`) đã có tag bài học và
tag câu hỏi **100%**, nên feedback đã đạt tầng meso cao nhất (`self_regulation`
— luôn có link ôn bài) và micro `kh`.

Thứ chặn tầng cao nhất là **misconception trên phương án nhiễu**: thiếu nó thì
không bao giờ lên `km` (giải thích em nhầm gì) hay `elaborated` (nhầm gì + ôn ở
đâu). Đây là phần lesson-as-tag **cố ý không tự động hoá**, vì nó đòi hiểu biết
chuyên môn về chỗ học viên hay sai.

## Chỉ mcq và true_false được tag

| Loại | Vì sao |
|---|---|
| `mcq`, `true_false` | ✅ response là id phương án đã chọn → khớp đúng |
| `matching` | ❌ response là cặp ghép, không phải id → không bao giờ khớp, tag vào nằm chết |
| `ordering` | ❌ response chứa **toàn bộ** id phương án ([grading.ts:63](../packages/core-lms/src/quizzes/grading.ts)) → `selectedIds.includes(o.id)` luôn đúng ⇒ **khớp giả mọi lượt** |

Khối lượng: `thiet-ke-ui-ux` 409 phương án / 175 câu · `tieng-trung-co-so-3`
38 phương án / 21 câu.

| # | Given / When / Then |

## Nhóm 2 — Script đề xuất (chỉ đọc)

| # | Given / When / Then |
|---|---|
| 2.1 | Chỉ lấy câu `mcq`/`true_false` có ≥1 phương án sai **chưa** gắn misconception |
| 2.2 | Mỗi câu gọi LLM **một lần** cho tất cả phương án của câu đó, kèm danh mục 43 mã sẵn có |
| 2.3 | Ưu tiên tái dùng mã sẵn có; chỉ đề xuất mã mới khi thật sự khác |

| 2.5 | Phương án chỉ "sai" mà không lộ hiểu nhầm nào ⇒ trả `null`, **không** ép gán — ép gán tạo ra độ chính xác giả |
| 2.6 | Xuất JSON có đủ ngữ cảnh (tên bài, đề bài, nhãn phương án) để duyệt mà không cần tra DB |
| 2.7 | **Không ghi gì vào DB** ngoài `AiUsageLog` |

| # | Given / When / Then |
